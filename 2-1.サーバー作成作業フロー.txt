サーバー作成グループ 作業フロー
中小企業向け模擬エンタープライズネットワーク構築プロジェクト

1. サーバー作成グループの担当範囲
サーバー作成グループは、VirtualBox上に仮想サーバ基盤を構築し、CML上のネットワークと連携させる役割を担当する。
主な担当範囲は、DNS、DHCP、NTP、Web、File、監視、ログ管理、Jump Server、RADIUS、TACACS+、バックアップである。

今回のサーバー構成では、1台のサーバにすべてを集約するのではなく、役割ごとにVMを分離する。
これにより、障害発生時の影響範囲を小さくし、企業ネットワークに近い共通サーバ基盤を再現する。

2. サーバー構成案
以下の仮想サーバをVirtualBox上に構築する。

2.1 Infra-01
役割:
- DNS
- DHCP
- NTP

実装する機能:
- BINDによる名前解決
- DHCPによるIPアドレス配布
- chronyによる時刻同期
- NTP Authenticationへの対応
- DHCP relayを受ける構成への対応

2.2 App-01
役割:
- Web
- File

実装する機能:
- Apacheによる社内Webサーバ
- 部署別Web領域
- NFSまたはvsftpdによるファイル共有
- 部署別共有フォルダ
- 部長、課長、一般ユーザーの権限分離
- サーバ側の認証・認可によるアクセス制御

2.3 Ops-01
役割:
- 監視
- ログ管理

実装する機能:
- ZabbixまたはPrometheusによる監視
- rsyslogによるログ集約
- ネットワーク機器監視
- サーバ監視
- SNMPv3監視
- HTTP監視
- DNS監視
- DHCP監視
- アラート設定
- ダッシュボード作成

2.4 SecMgmt-01
役割:
- Jump Server
- RADIUS
- TACACS+

実装する機能:
- Jump Server経由の管理アクセス
- RADIUSによる802.1X/MAB用認証
- TACACS+によるネットワーク機器管理者認証
- 管理者権限分離
  - NetAdmin
  - NetOperator
  - Auditor
- TACACS+ Accounting
- 認証ログ保存
- AAA障害時のlocal fallbackを考慮した設計

2.5 Backup-01
役割:
- バックアップ保存
- 復元試験
- 世代管理

実装する機能:
- ネットワーク機器設定のバックアップ
- DNS zoneファイルのバックアップ
- DHCP設定のバックアップ
- chrony設定のバックアップ
- Webコンテンツのバックアップ
- File共有データのバックアップ
- Zabbix/Prometheus設定のバックアップ
- rsyslog設定のバックアップ
- RADIUS/TACACS+設定のバックアップ
- VirtualBox VMのバックアップ
- rsync等による差分バックアップ
- バックアップ帯域制限
- 夜間バックアップ
- 復元テスト

3. 作業全体フロー
サーバー作成グループは、以下の順序で作業を進める。

1. サーバー設計の確認
2. VirtualBox環境の準備
3. 各VMの作成
4. OS基本設定
5. 基盤サービス構築
6. 業務サービス構築
7. 監視・ログ管理サービス構築
8. 認証・管理サービス構築
9. バックアップサービス構築
10. CMLネットワークとの結合
11. サーバー単体試験
12. ネットワーク結合試験
13. 障害試験
14. 復旧手順・Runbook作成
15. ドキュメント整理

4. フェーズ1：サーバー設計の確認
作業内容:
- サーバー一覧を確定する
- 各サーバーの役割を確定する
- 各サーバーのIPアドレスを確認する
- 各サーバーの接続VLANを確認する
- ホスト名を決定する
- DNS名を決定する
- バックアップ対象を整理する
- CMLネットワーク担当とゲートウェイ、VLAN、名前解決方針をすり合わせる

確認する内容:
- VLAN60 サーバ用
- VLAN70 管理用
- VLAN80 監視・ログ用
- VLAN110 バックアップ用
- 各サーバーの固定IP
- DNSドメイン名
- デフォルトゲートウェイ
- DHCP relayの有無
- 管理VRF経由で必要な通信
- RADIUS/TACACS+の到達性
- Syslog/NTP/SNMPv3の到達性

成果物:
- サーバー設計書
- サーバー一覧表
- IPアドレス表
- ホスト名一覧
- サービス一覧
- バックアップ対象一覧

5. フェーズ2：VirtualBox環境準備
作業内容:
- VirtualBoxをインストールする
- 仮想ネットワーク設定を確認する
- CMLと接続するためのBridge接続またはHost-only接続を確認する
- 各VM用の仮想ディスクを作成する
- VMテンプレートを作成する
- 初期スナップショットを取得する

推奨VM構成:
- Infra-01: 2CPU、2〜4GB RAM
- App-01: 2CPU、4GB RAM
- Ops-01: 2〜4CPU、4〜8GB RAM
- SecMgmt-01: 2CPU、2〜4GB RAM
- Backup-01: 2CPU、4GB RAM、大きめのディスク

成果物:
- VM一覧
- VMスペック表
- VirtualBoxネットワーク設定メモ
- 初期スナップショット

6. フェーズ3：OS基本設定
作業内容:
- Linux OSをインストールする
- ホスト名を設定する
- 固定IPアドレスを設定する
- デフォルトゲートウェイを設定する
- DNS参照先を設定する
- SSHを有効化する
- 管理ユーザーを作成する
- sudo権限を設定する
- firewalldまたはufwを設定する
- パッケージを更新する
- 時刻同期の基本設定を行う

実装する機能:
- 固定IP設定
- SSH接続
- 管理ユーザー
- sudo
- 基本Firewall
- NTP/chronyの基本設定

成果物:
- OS初期設定手順書
- サーバー基本設定メモ
- 初期疎通確認結果

7. フェーズ4：Infra-01構築
作業内容:
- BINDをインストールする
- 正引きゾーンを作成する
- 必要に応じて逆引きゾーンを作成する
- DHCPサーバを構築する
- 部署ごとのDHCPスコープを設定する
- DHCP relayを受ける構成を確認する
- chronyを設定する
- NTP Authenticationを設定する

実装する機能:
- DNS名前解決
- DHCPアドレス配布
- 部署別DHCPスコープ
- NTP時刻同期
- NTP Authentication

確認項目:
- 各サーバー名を名前解決できる
- 各部署端末にDHCPでIPが配布される
- CML機器とサーバーが時刻同期できる
- NTP Authenticationが機能する

成果物:
- DNS zoneファイル
- DHCP設定ファイル
- chrony設定ファイル
- DNS試験結果
- DHCP試験結果
- NTP試験結果

- 部長、課長、一般ユーザーの権限差を設定する

12. フェーズ9：CMLとの結合
作業内容:
- CMLネットワーク担当と接続方式を確認する
- SERVER-ACCESS1経由でVirtualBoxサーバ群を接続する
- 第1段階ではSERVER-ACCESS1のみでCMLとVirtualBoxの接続を成功させる
- 第2段階ではSERVER-ACCESS2を追加し、サーバーアクセス層を冗長化する
- 各サーバーのゲートウェイ到達性を確認する
- 各サーバーから必要なネットワークへ疎通確認する

第1段階:
- SERVER-ACCESS1のみを使用
- CMLとVirtualBoxの基本接続を確立
- DNS/DHCP/Web/SSH/監視の結合を優先

第2段階:
- SERVER-ACCESS2を追加
- サーバーアクセス層を冗長化
- SERVER-ACCESS1障害時の到達性を確認
- SERVER-ACCESS2経由で通信継続できるか確認
- 必要に応じてSTP、LACP、VLAN trunkを調整

確認項目:
- CML機器から各サーバーへpingできる
- サーバーからCML機器へpingできる
- 社員PCからWebサーバへアクセスできる
- 管理PCからJump Serverへ接続できる
- Jump Serverから各ネットワーク機器へSSHできる
- 監視サーバからCML機器を監視できる
- Backup-01から各サーバーへ接続できる

成果物:
- CML・VirtualBox接続試験結果
- サーバー結合試験表
- 疎通確認表

- Runbookに従って復旧する
- 復旧時間と改善点を記録する

障害試験項目:
- DNS停止
- DHCP停止
- NTP停止
- Web停止
- File停止
- Ops-01停止
- Jump Server停止
- RADIUS停止
- TACACS+停止
- Backup-01停止
- Backup中のネットワーク帯域制限
- Backupデータからの復元

確認項目:
- 障害を検知できる
- 業務影響を説明できる
- 復旧手順が実行できる
- 80%業務継続要件を満たせるか確認できる

成果物:
- サーバー障害試験表
- 障害対応記録
- 復旧手順書
- Runbook
