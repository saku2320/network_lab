中小企業向け模擬エンタープライズネットワーク 要件定義書

1. 文書概要
本書は、ゼミ活動において制作する「中小企業向け模擬エンタープライズネットワーク」の要件を定義するものである。
本制作物では、CML（Cisco Modeling Labs）とVirtualBoxを用いて、実際の企業ネットワークに近い構成を模擬的に構築する。
ネットワーク設計、サーバ構築、認証、監視、ログ管理、バックアップ、障害対応までを対象とし、構築後の運用まで含めた総合的なインフラ環境を目指す。

2. 目的
本プロジェクトの目的は、50〜60名規模の中小企業を想定した社内インフラを設計・構築し、ネットワークおよびサーバの実践的な知識を習得することである。

目的は以下の通りである。
- エンタープライズネットワークの3層構造を理解する
- 部署ごとにネットワークを分離する
- 業務通信、管理通信、監視通信、バックアップ通信を整理する
- 冗長性と可用性を意識した構成にする
- 障害発生時でも主要業務を継続できるようにする
- 監視、ログ管理、バックアップ、復旧手順を整備する
- ゼミ発表および就職活動で説明できる成果物にする

3. 想定企業概要
3.1 会社規模
社員数50〜60名程度の中小企業を想定する。

3.2 部署構成
以下の5部署を想定する。
- 営業部
- 人事部
- 総務部
- システム開発部
- システム管理部

3.3 各部署の人数
各部署は10〜15名程度の人員を想定する。
将来的な人員増加に備え、各部署に割り当てるネットワークには余裕を持たせる。

3.4 役職構成
各部署には以下の役職を想定する。
- 部長：各部署に1名
- 課長：各部署に1名
- 一般ユーザー：その他の利用者

部長および課長は、一般ユーザーより高い権限を持つものとする。
ただし、役職ごとの細かなアクセス制御はネットワーク機器だけで実現するのではなく、主にサーバ側の認証・認可、ファイル権限、Webアプリケーション権限によって実現する。

4. プロジェクト範囲
4.1 対象範囲
- CML上の仮想ネットワーク構築
- VirtualBox上の仮想サーバ構築
- CMLとVirtualBoxの連携
- 部署別ネットワーク分離
- サーバ用ネットワーク構築
- 管理用ネットワーク構築
- 監視・ログ用ネットワーク構築
- バックアップ用ネットワーク構築
- 認証基盤の設計
- 監視、ログ、バックアップ、復旧手順の整備
- 障害試験および業務継続性確認

4.2 初期構築では必須対象外とするもの
- 実際のインターネット公開サービス
- 本番クラウド環境との接続
- 実在企業の業務システム再現
- 本格的な商用セキュリティ製品の導入
- 本格的な無線LANコントローラ環境
- 本番環境相当の大規模冗長ストレージ

5. 全体構成要件
5.1 ネットワーク構成
ネットワークは、エンタープライズネットワークの3層構造を意識して構築する。
- Core層
- Distribution層
- Access層

Access層は、ユーザー端末用のUser Access層と、サーバ収容用のServer Access層に分ける。

5.2 構成方針
CML上にネットワーク機器を配置し、VirtualBox上のサーバ群と接続する。
CMLとVirtualBoxの接続にはExternal ConnectorやBridge接続を利用する。

5.3 Server Access層の段階構築
第1段階：
SERVER-ACCESS1のみを利用し、CMLとVirtualBoxの接続を成功させる。
この段階では、DNS、DHCP、Web、SSH、監視などの基本通信を優先して確認する。

第2段階：
SERVER-ACCESS2を追加し、サーバアクセス層を冗長化する。
SERVER-ACCESS1障害時でも、SERVER-ACCESS2経由でサーバ群へ到達できる構成を目指す。

6. ネットワーク機能要件
6.1 VLAN要件
部署別および用途別にVLANを分離する。

想定VLANは以下の通りである。
- VLAN10：営業部
- VLAN20：人事部
- VLAN30：総務部
- VLAN40：システム開発部
- VLAN50：システム管理部
- VLAN60：サーバ用
- VLAN70：管理用
- VLAN80：監視・ログ用
- VLAN90：検証・ゲスト用
- VLAN100：新規事業用予備
- VLAN110：バックアップ用

6.2 IPアドレス要件
各VLANには、将来的な人員増加を考慮して/24程度のネットワークを割り当てる。

想定IPアドレス帯は以下の通りである。
- VLAN10  営業部：10.10.10.0/24
- VLAN20  人事部：10.10.20.0/24
- VLAN30  総務部：10.10.30.0/24
- VLAN40  システム開発部：10.10.40.0/24
- VLAN50  システム管理部：10.10.50.0/24
- VLAN60  サーバ用：10.10.60.0/24
- VLAN70  管理用：10.10.70.0/24
- VLAN80  監視・ログ用：10.10.80.0/24
- VLAN90  検証・ゲスト用：10.10.90.0/24
- VLAN100 新規事業用予備：10.10.100.0/24
- VLAN110 バックアップ用：10.10.110.0/24

6.3 ルーティング要件
Core層とDistribution層では、OSPFを用いて動的ルーティングを行う。
Distribution層では各VLANのSVIを作成し、VLAN間ルーティングを行う。

実装要件：
- Core-Distribution間はL3接続とする
- OSPFを利用する
- 必要に応じてpassive-interfaceを設定する
- 将来的な支社接続を考慮して、ルート集約しやすいアドレス設計とする

6.4 デフォルトゲートウェイ冗長要件
各VLANのデフォルトゲートウェイは、HSRPを用いて冗長化する。
待機系が完全に遊休化しないよう、VLANごとにactiveを分散する。

例：
DIST1 active：
- VLAN10 営業部
- VLAN30 総務部
- VLAN50 システム管理部
- VLAN80 監視・ログ用

DIST2 active：
- VLAN20 人事部
- VLAN40 システム開発部
- VLAN60 サーバ用
- VLAN110 バックアップ用

6.5 L2冗長要件
Access層では、Distribution層へのuplinkを冗長化する。
必要に応じてLACP EtherChannelを用いる。

実装要件：
- Rapid PVST+を使用する
- STP root primary/secondaryをVLANごとに分散する
- PortFastを適切に利用する
- BPDU Guardを有効化する
- UDLDを検討する
- LACP EtherChannelを検討する

7. 通信制御要件
7.1 部署間通信制御
各部署の端末は、自部署に関連する業務用Web/File領域へアクセス可能とする。
他部署の業務データやサーバ領域へのアクセスは禁止する。

7.2 システム管理部の通信要件
システム管理部は、管理業務上必要な範囲で全ネットワークおよび全サーバへアクセス可能とする。

7.3 管理通信要件
管理通信は管理用ネットワークを経由させる。
一般社員用ネットワークから管理用ネットワークへの直接アクセスは禁止する。

実装要件：
- 管理アクセスはJump Server経由とする
- ネットワーク機器への管理接続はSSHのみ許可する
- Telnetは禁止する
- VTY ACLによりSSH接続元を制限する
- 管理VRFにより管理通信と業務通信を分離する

7.4 バックアップ通信要件
バックアップ通信は、バックアップ用VLANを利用する。
業務通信を圧迫しないよう、バックアップは原則として夜間または低負荷時間帯に実行する。

実装要件：
- バックアップ用VLANを作成する
- Backup-01のみバックアップ対象サーバへ接続可能とする
- 社員端末からBackup-01への直接アクセスは禁止する
- QoSでバックアップ通信を低優先化する
- 障害時はバックアップ通信を停止または制限する

8. セキュリティ要件
8.1 基本セキュリティ要件
以下を実装する。
- SSHのみ許可
- Telnet禁止
- 不要ポートのshutdown
- 管理用ACL
- VTY ACL
- SNMPv3
- Syslog転送
- NTP Authentication
- 管理VRF
- Port Security
- DHCP Snooping
- Dynamic ARP Inspection
- BPDU Guard

8.2 認証要件
認証基盤としてAAAを導入する。

RADIUS：
- 802.1X
- MAB
- 社員端末のネットワーク接続認証

TACACS+：
- ネットワーク機器への管理者ログイン認証
- コマンド認可
- 管理者操作ログ記録
- Accounting

8.3 管理者権限要件
管理者権限は以下の3段階を想定する。

NetAdmin：
- 全機器へのSSH可能
- 設定変更可能
- 保存操作可能

NetOperator：
- showコマンド中心
- ping、traceroute可能
- 設定変更不可

Auditor：
- 閲覧専用
- 設定変更不可

8.4 認証障害時要件
RADIUSまたはTACACS+に障害が発生した場合に備え、local fallbackを設定する。
緊急時にはローカル管理者アカウントで復旧作業を実施できるようにする。

9. サーバ要件
9.1 サーバ構成
VirtualBox上に以下の仮想サーバを構築する。

Infra-01：
- DNS
- DHCP
- NTP

App-01：
- Web
- File

Ops-01：
- 監視
- ログ管理

SecMgmt-01：
- Jump Server
- RADIUS
- TACACS+

Backup-01：
- バックアップ保存
- 世代管理
- 復元試験

9.2 DNS要件
BINDを用いて社内名前解決を行う。
必要に応じて正引き、逆引きゾーンを作成する。
将来的にはPrimary/Secondary DNS構成を検討する。

9.3 DHCP要件
部署ごとにDHCPスコープを設定する。
Distribution層でDHCP relayを行う。

9.4 NTP要件
chronyを用いて時刻同期を行う。
NTP Authenticationを利用し、信頼したNTPサーバのみと同期する。

9.5 Web要件
Apacheを用いて社内Webサーバを構築する。
部署別Web領域を用意する。

9.6 File要件
NFSまたはvsftpdを利用してファイルサーバを構築する。
部署別ディレクトリを作成し、部長、課長、一般ユーザーでアクセス権限を分ける。

9.7 監視・ログ要件
ZabbixまたはPrometheusを利用して監視を行う。
rsyslogを利用してログを集中管理する。

9.8 認証・管理要件
SecMgmt-01をJump Server、RADIUS、TACACS+用サーバとして利用する。

9.9 バックアップ要件
Backup-01を用意し、サーバ設定、Webコンテンツ、ファイル共有データ、ネットワーク機器設定、認証サーバ設定などをバックアップする。

10. 可用性要件
10.1 ネットワーク可用性
以下の冗長構成を実装する。
- Core層の二重化
- Distribution層の二重化
- User Access層の二重化
- Server Access層の段階的二重化
- Access-Distribution間uplink冗長
- OSPFによる経路冗長
- HSRPによるゲートウェイ冗長
- VLANごとのactive分散
- EtherChannelによるリンク冗長
- STP root分散

10.2 サーバ可用性
共通サーバ基盤を採用するが、役割ごとにVMを分けることで障害範囲を限定する。
重要サービスについてはバックアップ、予備VM、復旧手順を用意する。

実装要件：
- DNS Primary/Secondaryを検討する
- Web予備VMを検討する
- Fileデータを定期バックアップする
- 各サーバのスナップショットを取得する
- 復元試験を行う
- Runbookを作成する

10.3 業務継続要件
障害発生時でも平常時の80%程度の業務継続を目標とする。

80%業務継続の条件：
- DNSが利用可能
- DHCPが利用可能
- 業務Webが利用可能
- 重要ファイル共有が利用可能
- 管理者がSSHで復旧作業可能
- 監視またはログ確認が可能
- システム管理部が管理アクセス可能

11. QoS・帯域制御要件
11.1 基本方針
障害時には、業務系および管理系通信を優先する。
バックアップ通信、ゲスト通信、検証通信、大容量転送は低優先または制限対象とする。

11.2 通信優先度
最優先：
- OSPF
- HSRP
- SSH
- TACACS+
- RADIUS
- SNMPv3
- NTP
- Syslog
- 監視アラート

高優先：
- 業務Web
- 業務File
- DNS
- DHCP
- 社内業務通信

低優先：
- バックアップ
- 大容量ファイル転送
- VMイメージ転送

最低優先：
- Guest/Lab VLAN
- 検証通信

11.3 障害時制御
片系uplink障害時には、残ったuplinkへ業務系・管理系通信を優先的に流す。
バックアップ通信は停止または帯域制限する。
Guest/Lab通信は制限する。

12. 支社接続要件
12.1 将来支社想定
将来的に同等規模の支社を設立する想定とし、本社と支社を接続できる設計にする。

12.2 接続方針
- 本社と支社はVPN接続を想定する
- Edgeルーターを経由して拠点間接続する
- 支社側も同様のVLAN設計を採用できるようにする
- 拠点ごとにアドレス帯を分ける
- ルート集約しやすいアドレス設計にする
- 将来的なWAN冗長化を考慮する

12.3 アドレス例
- 本社：10.10.0.0/16
- 支社A：10.20.0.0/16
- 支社B：10.30.0.0/16

20. まとめ
本要件定義書では、中小企業向け模擬エンタープライズネットワークの制作に必要な要件を整理した。
本プロジェクトでは、CMLとVirtualBoxを用いて、3層構造、部署別ネットワーク分離、共通サーバ基盤、認証、監視、ログ管理、バックアップ、冗長化、QoS、障害対応までを含めた総合的なインフラ環境を構築する。

最終的には、単なる通信確認にとどまらず、要件定義、設計、構築、試験、運用監視、障害対応までを一連の流れとして実施し、実際の企業ネットワークに近い制作物として完成させる。
