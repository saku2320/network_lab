中小企業向け模擬エンタープライズネットワーク 全体構成図 解説

1. 全体構成図の概要
本図は、50〜60名規模の中小企業を想定した模擬エンタープライズネットワークの全体構成を示したものである。
ネットワークはCML上に構築し、サーバ群はVirtualBox上に構築する。
CMLとVirtualBoxを連携させることで、ネットワーク機器、社員端末、サーバ、監視、認証、バックアップを含む企業インフラ全体を模擬的に再現する。

本構成では、エンタープライズネットワークの基本である3層構造を採用する。
3層構造とは、以下の3つの層で構成されるネットワーク設計である。

・Core層
・Distribution層
・Access層

さらにAccess層は、社員端末を接続するUser Access層と、仮想サーバ群を接続するServer Access層に分ける。
これにより、ユーザー端末とサーバ基盤を分離し、障害時の影響範囲やセキュリティ制御を明確にする。

2. CML環境
図の中央にあるCML環境は、ネットワーク機器を仮想的に構築する領域である。
CML上には、Core層、Distribution層、User Access層、Server Access層、Edge接続を配置する。

CML環境で構築する主な機器は以下の通りである。

・CORE1
・CORE2
・DIST1
・DIST2
・USER-ACCESS1
・USER-ACCESS2
・SERVER-ACCESS1
・SERVER-ACCESS2
・EDGE1
・External Connector

CMLを利用することで、実機を用意しなくてもルーティング、VLAN、HSRP、OSPF、ACL、QoS、冗長化などの設定や検証を行うことができる。

3. Core層
Core層は、ネットワーク全体の中心となる高速中継層である。
本構成では、CORE1とCORE2の2台で構成する。

Core層の主な役割は以下の通りである。

・Distribution層間の高速なL3中継
・ネットワーク全体のバックボーン
・OSPFによるルーティングの中心
・冗長経路の確保
・上位のEDGE1や将来の支社接続への中継

Core層では、できるだけシンプルなL3中継を行う。
細かな通信制御や部署間アクセス制御は、主にDistribution層で実施する。
これにより、Core層は高速性と安定性を重視した構成にできる。

4. Distribution層
Distribution層は、Core層とAccess層の間に位置し、各VLANの集約や通信制御を行う層である。
本構成では、DIST1とDIST2の2台で構成する。

Distribution層の主な役割は以下の通りである。

・各VLANのSVIを配置する
・VLAN間ルーティングを行う
・HSRPによりデフォルトゲートウェイを冗長化する
・OSPFでCore層と経路交換を行う
・ACLで部署間通信を制御する
・DHCP relayを行う
・User Access層とServer Access層を集約する
・管理通信、監視通信、サーバ通信を制御する

本構成では、DIST1とDIST2でHSRPのactiveをVLANごとに分散する。
これにより、一方のDistribution機器だけに通信が集中することを避け、active-activeに近い形で両方の機器を利用できる。

例として、以下のようなactive分散を想定する。

DIST1 active:
・VLAN10 営業部
・VLAN30 総務部
・VLAN50 システム管理部
・VLAN80 監視・ログ用

DIST2 active:
・VLAN20 人事部
・VLAN40 システム開発部
・VLAN60 サーバ用
・VLAN110 バックアップ用

5. User Access層
User Access層は、社員端末を収容するためのAccess層である。
図では、USER-ACCESS1とUSER-ACCESS2の2台で構成している。

User Access層に接続される端末は以下の通りである。

・営業部PC
・人事部PC
・総務部PC
・システム開発部PC
・システム管理部PC

User Access層では、部署ごとのVLANに端末を接続する。
各部署の端末は、自部署用のWeb領域やファイル領域へアクセスできるが、他部署の業務データにはアクセスできないようにする。

User Access層で実装する主な機能は以下の通りである。

・VLAN割り当て
・Accessポート設定
・Trunk設定
・Rapid PVST+
・PortFast
・BPDU Guard
・Port Security
・DHCP Snooping
・Dynamic ARP Inspection
・Distribution層への二重uplink

User Access層を2台構成にすることで、片方のAccessスイッチやuplinkに障害が発生した場合でも、可能な範囲で業務継続を行えるようにする。

6. Server Access層
Server Access層は、VirtualBox上に構築する仮想サーバ群を収容するためのAccess層である。
図では、SERVER-ACCESS1とSERVER-ACCESS2の2台を配置している。

Server Access層の主な役割は以下の通りである。

・サーバ用VLANの収容
・管理用VLANの収容
・監視・ログ用VLANの収容
・バックアップ用VLANの収容
・VirtualBox仮想サーバ群とCMLネットワークの接続
・Distribution層への冗長接続

重要な点として、Server Access層は段階的に構築する。

第1段階:
SERVER-ACCESS1のみを使用し、CMLとVirtualBoxの接続を成功させる。
この段階では、構成を単純にして、まず基本通信を成立させることを優先する。
確認する通信は、DNS、DHCP、NTP、Web、SSH、監視、Syslogなどである。

第2段階:
SERVER-ACCESS2を追加し、Server Access層を冗長化する。
これにより、SERVER-ACCESS1に障害が発生した場合でも、SERVER-ACCESS2経由でサーバ群へ到達できる構成を目指す。

この段階的な構築方針により、最初から複雑な冗長構成にすることによるトラブルを避けつつ、最終的には企業ネットワークに近い可用性を実現できる。

7. VirtualBox仮想サーバ群
図の右側には、VirtualBox上に構築する仮想サーバ群を示している。
サーバは1台にすべて集約するのではなく、役割ごとに分けて構築する。

7.1 Infra-01
Infra-01は、基盤系サービスを担当するサーバである。

役割:
・DNS
・DHCP
・NTP

使用想定:
・BINDによる名前解決
・DHCPによるIPアドレス配布
・chronyによる時刻同期
・NTP Authenticationへの対応

7.2 App-01
App-01は、業務系サービスを担当するサーバである。

役割:
・Web
・File

使用想定:
・Apacheによる社内Webサーバ
・部署別Web領域の提供
・NFSまたはvsftpdによるファイル共有
・部署別ファイル領域の提供
・役職ごとのアクセス制御

7.3 Ops-01
Ops-01は、運用監視とログ管理を担当するサーバである。

役割:
・監視
・Syslog

使用想定:
・ZabbixまたはPrometheusによる監視
・rsyslogによるログ集約
・ネットワーク機器やサーバの死活監視
・CPU、メモリ、インターフェース状態の監視
・障害発生時のアラート通知

7.4 SecMgmt-01
SecMgmt-01は、管理・認証系サービスを担当するサーバである。

役割:
・Jump Server
・RADIUS
・TACACS+

使用想定:
・管理者はJump Server経由でネットワーク機器へSSH接続する
・RADIUSは802.1XやMABなどの端末認証に使用する
・TACACS+はネットワーク機器の管理者認証、コマンド認可、操作ログ記録に使用する

7.5 Backup-01
Backup-01は、バックアップと復元を担当するサーバである。

役割:
・バックアップ保存
・世代管理
・復元試験

バックアップ対象:
・ネットワーク機器設定
・CMLトポロジ
・DNS設定
・DHCP設定
・Webコンテンツ
・ファイル共有データ
・監視設定
・RADIUS/TACACS+設定
・VirtualBox VM
・設計書類

8. EDGE1と将来の支社接続
図の上部には、EDGE1と将来の支社接続/VPNを示している。
EDGE1は、本社ネットワークと外部ネットワーク、または将来の支社を接続するための境界装置として扱う。

本プロジェクトの初期段階では、実際にインターネットへ公開することは想定しない。
ただし、将来的に支社を追加することを想定し、EDGE1を配置しておく。

支社接続の想定:
・本社と支社をVPNで接続する
・本社は10.10.0.0/16を使用する
・支社Aは10.20.0.0/16を使用する
・支社Bは10.30.0.0/16を使用する
・拠点ごとにアドレス帯を分け、ルート集約しやすい設計にする

9. VLAN構成
本構成では、部署別および用途別にVLANを分ける。

VLAN一覧:
・VLAN10：営業部
・VLAN20：人事部
・VLAN30：総務部
・VLAN40：システム開発部
・VLAN50：システム管理部
・VLAN60：サーバ用
・VLAN70：管理用
・VLAN80：監視・ログ用
・VLAN90：検証・ゲスト用
・VLAN100：新規事業用予備
・VLAN110：バックアップ用

部署ごとにVLANを分けることで、部署間の不要な通信を制限できる。
また、管理用、監視用、バックアップ用のVLANを分けることで、通常業務通信と運用管理通信を分離できる。

10. 管理アクセスの流れ
管理アクセスは、社員用ネットワークから直接ネットワーク機器へ行うのではなく、管理用ネットワークとJump Serverを経由して行う。

管理アクセスの流れ:
管理用PC
→ 管理用VLAN
→ Jump Server
→ CML上のネットワーク機器
→ 必要に応じて各サーバ

この方式により、管理アクセスの入口を限定できる。
また、TACACS+と連携することで、誰がどの機器にログインし、どの操作を行ったかを記録できる。

11. 業務通信の流れ
社員端末は、所属部署のVLANに接続される。
各部署の端末は、Distribution層でルーティングされ、必要なサーバ用VLANへアクセスする。

例:
営業部PC
→ USER-ACCESS1またはUSER-ACCESS2
→ DIST1またはDIST2
→ SERVER-ACCESS1またはSERVER-ACCESS2
→ App-01の営業部用Web/File領域

他部署の業務データには、ACLやサーバ側の権限設定によりアクセスできないようにする。

12. 監視・ログ通信の流れ
Ops-01は、ネットワーク機器やサーバを監視する。
また、各機器やサーバのログはrsyslogによりOps-01へ集約される。

監視・ログ通信の例:
・CML機器 → Ops-01へSyslog送信
・サーバ → Ops-01へSyslog送信
・Ops-01 → CML機器へSNMPv3監視
・Ops-01 → サーバへ死活監視
・Ops-01 → Web/DNS/DHCPなどのサービス監視

監視・ログ通信はVLAN80を中心に扱う。

13. バックアップ通信の流れ
Backup-01は、各サーバやネットワーク機器の設定をバックアップする。
バックアップ通信はVLAN110を利用し、通常業務通信とは分離する。

バックアップ通信の例:
・Backup-01 → Infra-01
・Backup-01 → App-01
・Backup-01 → Ops-01
・Backup-01 → SecMgmt-01
・Backup-01 → ネットワーク機器設定

バックアップは通信量が多くなりやすいため、原則として夜間や低負荷時間帯に実行する。
また、障害発生時には業務通信や管理通信を優先するため、バックアップ通信は停止または帯域制限する。

14. 冗長化設計
本構成では、以下のように冗長性を確保する。

・CORE1とCORE2によるCore層冗長
・DIST1とDIST2によるDistribution層冗長
・USER-ACCESS1とUSER-ACCESS2によるUser Access冗長
・SERVER-ACCESS1とSERVER-ACCESS2によるServer Access冗長
・HSRPによるデフォルトゲートウェイ冗長
・OSPFによる経路冗長
・EtherChannelによるリンク冗長
・STP root分散によるL2冗長
・バックアップとRunbookによるサーバ復旧性の確保

15. 障害時の考え方
本構成では、障害発生時でも平常時の80%程度の業務継続を目標とする。

優先して維持するもの:
・DNS
・DHCP
・業務Web
・重要ファイル共有
・管理者のSSH接続
・Jump Server経由の管理アクセス
・監視またはログ確認
・システム管理部による復旧作業

障害時に制限するもの:
・バックアップ通信
・Guest/Lab通信
・検証通信
・大容量ファイル転送
・緊急性の低いログアーカイブ転送

QoSにより、管理系通信、業務系通信、監視通信を優先し、バックアップやゲスト通信を低優先にする。

16. この構成図の重要ポイント
本構成図の重要ポイントは以下である。

・3層構造を採用している
・Core層、Distribution層、Access層の役割が分かれている
・User Access層とServer Access層を分離している
・VirtualBoxサーバ群をServer Access層に接続している
・Server Access層は段階的に冗長化する
・部署ごとにVLANを分けている
・管理、監視、バックアップ用ネットワークを分離している
・Jump Server、RADIUS、TACACS+を用いて管理アクセスを制御する
・監視、ログ、バックアップまで含めた運用設計になっている
・将来的な支社接続を想定してEDGE1を配置している
・障害時の業務継続を意識している

17. まとめ
本全体構成図は、中小企業向けの模擬エンタープライズネットワークをCMLとVirtualBoxで構築するための全体像を示している。
ネットワークはCore、Distribution、Accessの3層構造とし、Access層をUser AccessとServer Accessに分けることで、ユーザー端末とサーバ基盤を明確に分離している。

また、Server Access層については、まずSERVER-ACCESS1のみでCMLとVirtualBoxの接続を成功させ、その後SERVER-ACCESS2を追加して冗長化する段階的な構築方針を採用している。
これにより、構築の難易度を抑えながら、最終的には企業ネットワークに近い可用性を持つ構成へ発展させることができる。

本構成は、部署分離、サーバ基盤、管理ネットワーク、監視・ログ、認証、バックアップ、QoS、障害対応、支社接続を含んでおり、ゼミ制作物としてだけでなく、就職活動においても説明しやすい実践的なインフラ構成である。
