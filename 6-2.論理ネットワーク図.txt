論理ネットワーク図 解説
中小企業向け模擬エンタープライズネットワーク

1. 論理ネットワーク図の概要
本図は、中小企業向け模擬エンタープライズネットワークにおける論理構成を示したものである。
物理的なケーブル接続そのものよりも、VLAN、IPアドレス、ルーティング、冗長化、通信制御、管理ネットワーク、サーバネットワークの関係を分かりやすく表すことを目的としている。

本ネットワークは、Core層、Distribution層、Access層の3層構造を基本とする。
Access層は、社員端末を収容するUser Access層と、仮想サーバ群を収容するServer Access層に分ける。
これにより、利用者端末とサーバ基盤を論理的に分離し、通信制御や障害時の影響範囲を整理しやすくしている。

2. 論理構成の基本方針
本図では、以下の考え方を前提としている。

・部署ごとにVLANを分ける
・サーバ用、管理用、監視・ログ用、バックアップ用のVLANを分離する
・Distribution層でVLAN間ルーティングを行う
・HSRPにより各VLANのデフォルトゲートウェイを冗長化する
・Core層とDistribution層はOSPFにより動的ルーティングを行う
・Access層ではL2接続を中心とし、Distribution層へ集約する
・Server Access層は段階的に構築し、最終的に冗長化する
・管理アクセスはJump Server経由に限定する
・バックアップ通信や検証通信は低優先とする

3. VLAN設計
本ネットワークでは、部署別および用途別にVLANを分ける。
VLANを分けることで、部署間の不要な通信を制限し、セキュリティと管理性を高める。

3.1 部署別VLAN
各部署には専用VLANを割り当てる。

・VLAN10：営業部
・VLAN20：人事部
・VLAN30：総務部
・VLAN40：システム開発部
・VLAN50：システム管理部

部署別VLANの目的:
・部署ごとの通信範囲を明確にする
・他部署の業務データへの不要なアクセスを防ぐ
・ACLによる通信制御を行いやすくする
・将来的な人員増加にも対応しやすくする

3.2 用途別VLAN
部署別VLANとは別に、サーバ、管理、監視、バックアップなどの用途別VLANを用意する。

・VLAN60：サーバ用
・VLAN70：管理用
・VLAN80：監視・ログ用
・VLAN90：検証・ゲスト用
・VLAN100：新規事業用予備
・VLAN110：バックアップ用

用途別VLANの目的:
・業務通信と管理通信を分離する
・監視通信とログ収集通信を整理する
・バックアップ通信を業務通信から分離する
・検証やゲスト利用が本番業務に影響しないようにする
・将来的な新規事業用ネットワークを確保する

4. IPアドレス設計
本ネットワークでは、各VLANに/24のネットワークを割り当てる。
現在の想定利用者数は50〜60名程度であるが、将来的な人員増加やサーバ追加を考慮して余裕を持たせる。

想定IPアドレス帯:
・VLAN10 営業部：10.10.10.0/24
・VLAN20 人事部：10.10.20.0/24
・VLAN30 総務部：10.10.30.0/24
・VLAN40 システム開発部：10.10.40.0/24
・VLAN50 システム管理部：10.10.50.0/24
・VLAN60 サーバ用：10.10.60.0/24
・VLAN70 管理用：10.10.70.0/24
・VLAN80 監視・ログ用：10.10.80.0/24
・VLAN90 検証・ゲスト用：10.10.90.0/24
・VLAN100 新規事業用予備：10.10.100.0/24
・VLAN110 バックアップ用：10.10.110.0/24

各VLANのデフォルトゲートウェイは、Distribution層のHSRP仮想IPとして提供する。
例として、VLAN10では10.10.10.1をHSRPの仮想ゲートウェイとする。

5. Core層の役割
Core層は、ネットワーク全体の中心となるL3中継層である。
図ではCORE1とCORE2を配置している。

Core層の役割:
・Distribution層間の高速L3中継
・OSPFによるバックボーンルーティング
・外部接続や将来の支社接続への中継
・冗長経路の提供

Core層では、細かなACLや利用者ごとの通信制御は基本的に行わない。
Core層はできるだけシンプルにし、高速で安定した中継を行うことを重視する。

6. Distribution層の役割
Distribution層は、VLAN間ルーティング、HSRP、ACL、DHCP relayなどを担当する層である。
図ではDIST1とDIST2を配置している。

Distribution層の役割:
・各VLANのSVIを持つ
・VLAN間ルーティングを行う
・HSRPによりデフォルトゲートウェイを冗長化する
・ACLにより部署間通信を制御する
・DHCP relayによりDHCPサーバへ中継する
・Core層とOSPFで接続する
・User Access層とServer Access層を集約する

Distribution層は、ネットワークポリシーを適用する中心的な場所である。
社員端末からサーバへの通信、部署間通信、管理通信、監視通信、バックアップ通信などは、Distribution層で制御する。

7. Access層の役割
Access層は、端末やサーバを収容する層である。
本構成では、User Access層とServer Access層に分けている。

7.1 User Access層
User Access層は、社員PC、無線AP、IP電話、プリンタなどを接続する領域である。

User Access層の役割:
・部署ごとの端末を収容する
・各端末を適切なVLANへ接続する
・Distribution層へuplinkする
・Accessポートのセキュリティを実装する

実装する主な機能:
・Accessポート設定
・Trunk設定
・PortFast
・BPDU Guard
・Port Security
・DHCP Snooping
・Dynamic ARP Inspection
・Rapid PVST+
・必要に応じたLACP EtherChannel

7.2 Server Access層
Server Access層は、VirtualBox上の仮想サーバ群を収容する領域である。

Server Access層の役割:
・サーバ用VLANを収容する
・管理用VLANを収容する
・監視・ログ用VLANを収容する
・バックアップ用VLANを収容する
・VirtualBox仮想サーバ群とCMLネットワークを接続する
・Distribution層へ冗長接続する

8. Server Access層の段階構築
本構成では、Server Access層を段階的に構築する。

8.1 第1段階
第1段階では、SERVER-ACCESS1のみでCMLとVirtualBoxの接続を成功させる。

目的:
・構成を単純化する
・CMLとVirtualBoxの接続方式を確認する
・基本通信を早期に成立させる
・DNS、DHCP、Web、SSH、監視などのサービス結合を優先する

第1段階で確認する通信:
・CML機器から各サーバへのping
・社員PCからWebサーバへのアクセス
・DHCPによるIP配布
・DNS名前解決
・管理PCからJump ServerへのSSH
・監視サーバからネットワーク機器への監視

8.2 第2段階
第2段階では、SERVER-ACCESS2を追加し、Server Access層を冗長化する。

目的:
・Server Access層の単一障害点を減らす
・SERVER-ACCESS1停止時でもサーバ群へ到達できるようにする
・Distribution層との冗長接続を確認する
・サーバ基盤の可用性を高める

第2段階で確認する通信:
・SERVER-ACCESS1停止時のサーバ到達性
・SERVER-ACCESS2停止時のサーバ到達性
・DIST1停止時のサーバ到達性
・DIST2停止時のサーバ到達性
・バックアップ通信の継続または制限
・監視アラートの発生

9. ルーティング設計
本ネットワークでは、Core層とDistribution層の間でOSPFを使用する。
Distribution層は各VLANのデフォルトゲートウェイを持ち、VLAN間ルーティングを行う。

ルーティング方針:
・Core-Distribution間はL3接続とする
・OSPF Area 0を使用する
・Access層は基本的にL2とする
・各VLANのSVIはDistribution層に配置する
・外部接続や将来の支社接続はEDGE1経由を想定する

この構成により、Core層、Distribution層間で経路冗長を確保し、片系障害時にも経路を切り替えられるようにする。

10. HSRPによるゲートウェイ冗長
各VLANのデフォルトゲートウェイは、DIST1とDIST2でHSRPを構成して提供する。
ユーザー端末やサーバから見たデフォルトゲートウェイは、HSRPの仮想IPとなる。

HSRPを利用する目的:
・Distribution層の片系障害時でもゲートウェイを継続する
・端末側のデフォルトゲートウェイ設定を変更せずに済む
・VLANごとにactiveを分散できる

active分散例:
DIST1 active:
・VLAN10 営業部
・VLAN30 総務部
・VLAN50 システム管理部
・VLAN80 監視・ログ用

DIST2 active:
・VLAN20 人事部
・VLAN40 システム開発部
・VLAN60 サーバ用
・VLAN110 バックアップ用

このようにVLANごとにactiveを分けることで、待機系が完全に遊休状態になることを避ける。

11. STPとL2冗長
Access層ではL2接続が多くなるため、STPによるループ対策が重要である。
本構成ではRapid PVST+を想定する。

実装方針:
・VLANごとにSTP root primary/secondaryを分散する
・AccessポートではPortFastを有効化する
・AccessポートではBPDU Guardを有効化する
・不正なスイッチ接続やループを防止する
・uplinkでは必要に応じてLACP EtherChannelを使用する

STP rootの分散により、HSRPのactive側とL2経路を合わせる設計も検討する。

12. 管理ネットワーク
管理ネットワークはVLAN70として分離する。
管理PCやJump Server、管理用通信はこのネットワークを利用する。

管理通信の流れ:
管理PC
→ VLAN70 管理用ネットワーク
→ Jump Server
→ CML上のネットワーク機器
→ 必要に応じて各サーバ

管理アクセスの方針:
・管理アクセスはJump Server経由に限定する
・SSHのみ許可する
・Telnetは禁止する
・VTY ACLで接続元を制限する
・TACACS+で管理者認証を行う
・管理VRFにより業務通信と分離する

13. 監視・ログネットワーク
監視・ログネットワークはVLAN80として分離する。
Ops-01が監視とログ収集を担当する。

監視・ログ通信の例:
・ネットワーク機器からOps-01へSyslog送信
・各サーバからOps-01へSyslog送信
・Ops-01からネットワーク機器へSNMPv3監視
・Ops-01からサーバへ死活監視
・HTTP、DNS、DHCPなどのサービス監視

監視・ログネットワークを分けることで、通常業務通信と運用管理通信を整理できる。

14. バックアップネットワーク
バックアップネットワークはVLAN110として分離する。
Backup-01が各サーバやネットワーク機器の設定をバックアップする。

バックアップ対象:
・ネットワーク機器設定
・CMLトポロジ
・DNS設定
・DHCP設定
・NTP設定
・Webコンテンツ
・File共有データ
・監視設定
・RADIUS/TACACS+設定
・VirtualBox VM
・設計書類

バックアップ通信は通信量が多くなりやすいため、QoSで低優先とする。
また、障害時には業務通信や管理通信を優先するため、バックアップ通信を停止または制限する。

15. 業務通信の流れ
各部署のPCはUser Access層に接続され、Distribution層を経由してサーバ用VLANへアクセスする。

例:
営業部PC
→ USER-ACCESS1またはUSER-ACCESS2
→ DIST1またはDIST2
→ SERVER-ACCESS1またはSERVER-ACCESS2
→ App-01の営業部用Web/File領域

他部署のデータへは、ACLやサーバ側の権限設定によりアクセスできないようにする。

16. 通信制御
本ネットワークでは、部署間通信や管理通信をACLで制御する。

基本方針:
・各部署PCは自部署のWeb/File領域へアクセス可能
・他部署の業務データにはアクセス不可
・システム管理部は全ネットワークへ管理アクセス可能
・社員VLANから管理VLANへの直接アクセスは禁止
・Guest/Lab VLANから業務ネットワークへのアクセスは禁止
・Backup VLANはBackup-01と管理者のみ利用可能

17. QoSと障害時の帯域制御
active-active構成では、片系障害時に残ったuplinkへ通信が集中する。
そのため、QoSにより通信の優先度を設定する。

最優先:
・OSPF
・HSRP
・SSH
・TACACS+
・RADIUS
・SNMPv3
・NTP
・Syslog
・監視アラート

高優先:
・業務Web
・業務File
・DNS
・DHCP
・社内業務通信

低優先:
・バックアップ
・大容量ファイル転送
・VMイメージ転送

最低優先:
・Guest/Lab VLAN
・検証通信

障害時には、業務系および管理系通信を優先し、バックアップ通信や検証通信を制限する。

18. 外部接続と支社接続
図では、EDGE1やFW/Routerを通じて外部接続や将来の支社接続を想定している。

支社接続方針:
・本社と支社はVPN接続を想定する
・本社は10.10.0.0/16を利用する
・支社Aは10.20.0.0/16を利用する
・支社Bは10.30.0.0/16を利用する
・拠点ごとにアドレスを分け、ルート集約しやすくする

初期構築では外部公開を行わず、将来拡張として支社接続を設計に含める。

19. この論理ネットワーク図の重要ポイント
本図の重要ポイントは以下である。

・3層構造を採用している
・部署別にVLANを分離している
・サーバ用、管理用、監視用、バックアップ用VLANを分離している
・Distribution層でVLAN間ルーティングとACL制御を行う
・HSRPによりデフォルトゲートウェイを冗長化する
・VLANごとにactiveを分散し、active-activeに近い構成にする
・Core層とDistribution層はOSPFで冗長化する
・User Access層とServer Access層を分けている
・Server Access層は第1段階と第2段階に分けて構築する
・管理アクセスはJump Server経由に限定する
・監視、ログ、バックアップまで論理設計に含めている
・QoSにより障害時の業務継続を考慮している
・将来的な支社接続を見据えている

20. まとめ
本論理ネットワーク図は、模擬エンタープライズネットワークにおけるVLAN、ルーティング、冗長化、通信制御、管理ネットワーク、サーバネットワークの関係を示したものである。

部署ごとにVLANを分け、Distribution層でSVI、HSRP、ACLを管理することで、企業ネットワークに近い設計を実現している。
また、User Access層とServer Access層を分離し、サーバ基盤は段階的に冗長化する方針としている。

本構成により、構築しやすさと実企業らしさの両方を確保しながら、最終的には障害発生時にも平常時の80%程度の業務継続を目指すネットワークを実現する。
